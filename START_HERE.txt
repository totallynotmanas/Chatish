🔐 HOW SECURITY WORKS (Transparent to User)

User sends: "Hello"
         ↓
   [Hash password + verify OTP]
         ↓
   [Derive session key via DH]
         ↓
   [AES-256-GCM encrypt message]
         ↓
   [Compute HMAC-SHA256 signature]
         ↓
   [Base64 encode for TCP safety]
         ↓
   TCP Transmission (binary encrypted data)
         ↓
   [Base64 decode]
         ↓
   [Verify HMAC-SHA256 signature]
         ↓
   [AES-256-GCM decrypt message]
         ↓
   [Check role-based authorization]
         ↓
Server displays: "alice: Hello" (encrypted throughout)

❓ COMMON QUESTIONS

Q: Do I need Go installed?
A: No. chatish.exe is a standalone binary.

Q: How do I get the OTP?
A: Server prints it to console when you try to login.

Q: Why can't I access VIP room?
A: Your role doesn't have permission. Check credentials.

Q: Is my traffic encrypted?
A: Yes. All messages use AES-256-GCM encryption.

Q: Can I modify messages in transit?
A: No. HMAC-SHA256 detects tampering. Modified messages rejected.

Q: Can multiple users chat simultaneously?
A: Yes. Web + CLI clients can all connect to same server.

Q: What if the server crashes?
A: Clients disconnect gracefully. Restart and reconnect.

Q: Is this production-ready?
A: Development version. For production: add TLS, secure OTP delivery.

Q: How do I add more users?
A: Modify server.go users map (line ~30).

Q: Can I export chat history?
A: Not in current version. Messages stay in memory only.
